工作区知识库 M3 详细设计

归档 被 3 处引用 sdemo.kb/doc/01H9…@v7#b4 来源：手工撰写·4 块 · 1.2 KB 文本
派生状态 已就绪

1. 目标与非目标

#b1 · p.1

把当前工作区里已归档的会话变成可检索的知识，而不是每轮把历史塞进上下文。默认上下文成本为 0；开启后系统提示只多一句「本工作区有 N 条归档会话」。

#b2 · p.1

非目标：不做向量库、不做 embedding、不做跨工作区检索。检索与正文都走工具结果预算：单次检索 ≤800 token，正文按 MidTurnToolResultChars 分页。

#b3 · p.2

2.2 FTS5 索引

索引与归档会话放在同一个工作区 SQLite 文件里，避免跨库一致性问题。中文连续段按 2-gram 预分词；拉丁字母与数字小写化；标题 ×4、摘要 ×3、正文 ×1 重复写入，用 bm25 的 tf 近似实现「摘要优先」。

#b4 · p.3

3. 数据模型

五个概念：文档 kb_doc、版本 kb_version、块 kb_block、变更 kb_change、引用 kb_link。版本只增不改，编辑 = 新版本 + 新块；块正文按 content_hash 存一份，版本只引用块 id。

#b5 · p.3

内容寻址让「改一段」的存储代价变成 O(改动量)：五十个版本不是五十倍存储。

#b6 · p.4
